# 队友Q2流程图核对与新版图说明

## 核对结论

原图的主干基本正确：三模态输入、局部连续缺失、三分支CNN、掩码池化、缺失感知门控和分类/强度双头均与采用的M3一致。但有以下需要更正或补明的实现细节。

1. 原图将Text(50×768)放在原始输入处，却没有冻结BERT步骤。50×768是BERT编码后的表示；实际读取text_bert(3×50)，而非官方预存text。缺失token必须先改PAD、attention置0，再冻结编码，最后屏蔽对应输出。缺失应作用在输入端，不能画成完整编码后才遮挡。
2. aligned_50已存为最多50个位置。“统一样本时序长度”宜改为“核验50位置接口、原始内容域及padding”，不能暗示重新均匀采样或50位置都是有效词/时间片。
3. 43=1个清洁场景+42个缺失场景。原图末行“43个缺失场景”应改为“43个评价场景”。比例按有效特征位置计算，不是已知秒级时长；同一批样本复用，不是43份独立测试集。
4. 正式训练使用一次生成的固定增强清单，不是每个epoch重新随机缺失。3395条中1671条清洁、1724条被标记增强；43场景用于系统评价，不是每个训练样本扩增43倍。
5. 应补上仅由clean train拟合的标准化、P/O/M定义及原生零行不自动判缺失。quality是可观测位置比例，不是人脸检测、音质或语义可信度。
6. Masked Temporal Pooling实际是掩码平均池化，未采用注意力池化；三分支参数独立。门控由模态表示和可观测比例共同决定，不仅由缺失率手工分配。
7. 原图没有训练损失和选权：CE+MAE/3；逐轮取最低清洁验证联合损失，候选M0–M3再按预定清洁约束及43场景表现选M3。没有改为按最高Accuracy选权。
8. 当前需要加入冻结后的附件2 test终检：483/727=66.44%；验证仍为457/728=62.77%。附件3的30条无标签专项预测不能报告准确率，亦不能将66.44%归到附件3。

因此原图可以作为交流草图，但不建议不修改就作为严格对应当前代码的论文最终图。

## 编辑与复现

每张SVG的文字为原生text元素，节点和连线为矢量形状，未把文字转轮廓，也不是将PNG封装进SVG。语义节点带有ID，便于在矢量编辑器中选取。字体为Microsoft YaHei；队友电脑缺少该字体时可统一替换，但替换后需检查换行。

同名PNG仅为方便预览，和SVG由同一绘图对象直接导出。所有原有PNG/SVG及队友原图不覆盖。新版独立目录中的文件可直接交给队友。

生成代码：code/figures/technical_routes.py。它只读取保存报告/配置与源码哈希，不加载竞赛特征、不训练或推理。默认输出目录拒绝覆盖；复现时指定新的目录：

```powershell
& 'D:/anaconda3/envs/mathmodel/python.exe' -X utf8 -B 'D:/个人资料/数学建模比赛/E题解答/code/figures/technical_routes.py' --output-dir 'D:/个人资料/数学建模比赛/E题解答/figures/technical_routes/TECH_ROUTES_REPRO_001'
```

sources.json绑定采用来源、当前源码与字体；layout_checks.json记录文字边界、文字互不重叠和连线不穿过节点/文字的自动检查。视觉检查另行记录，不把版面通过称为研究结论全部通过。
